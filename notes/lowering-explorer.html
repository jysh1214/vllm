How to read it. Platform / Hardware sits at the top because it's an auto-detected environment fact (current_platform, resolved from the installed wheel + visible devices) — not a config choice — and it gates everything below. (The old separate "Hardware target" layer is merged in: it was a 1:1 function of platform.) Compilation mode (the CompilationMode enum) and torch.compile backend (the backend field) are config you set; the backend layer is disabled when mode = NONE. For Custom / Triton / External kernels both are inert (opaque to torch.compile), so the Launch mechanism is the same in every mode. The exception is Native ops: mode≠NONE with backend=inductor → Inductor codegen (Triton on GPU, C++/OpenMP on CPU); backend=eager → ATen (graph captured, no codegen); openxla → XLA on TPU. Launch mechanism is derived from source + platform (+ compile mode/backend, for native).
